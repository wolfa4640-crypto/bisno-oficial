BISNO — MARKETPLACE PARA ANGOLA (v2.0)
======================================

Este pacote mantém o projeto Bisno e acrescenta melhorias de segurança básica e persistência das sessões: armazenamento SQLite para sessões (elimina o aviso MemoryStore), cabeçalhos Helmet, limitação de pedidos e configuração de publicação.

FUNCIONALIDADES PRESENTES NO PROJETO
- Registo e autenticação de utilizadores.
- Publicação, pesquisa e visualização de anúncios.
- Imagens, perfil e informação de contacto de vendedores.
- Mensagens, conversas e notificações do marketplace.
- Interface responsiva para computador e telemóvel.
- Base de dados SQLite no diretório data/.

PUBLICAR NO RENDER
1. Carrega os ficheiros e pastas mantendo a estrutura, incluindo public/, routes/, middleware/, data/ e uploads/.
2. Não carregues node_modules/ nem .env.
3. No Render, configura Build Command: npm install
4. Configura Start Command: npm start (ou node server.js).
5. Adiciona Environment Variable: SESSION_SECRET com um segredo aleatório forte de pelo menos 32 caracteres.
6. Define NODE_ENV=production.
7. Faz deploy e consulta os logs. O aviso MemoryStore deve desaparecer porque as sessões usam SQLiteStore.

IMPORTANTE SOBRE DADOS PERMANENTES
A sessão agora é guardada em SQLite em vez da memória do processo. No entanto, tanto a base de dados marketplace.db como as sessões e as imagens em uploads/ dependem do disco local. No plano gratuito do Render, o disco local pode ser efémero; para um marketplace público, configura um Persistent Disk ou migra a base de dados para PostgreSQL e as imagens para armazenamento de objetos persistente. Não publiques dados de utilizadores ou segredos no repositório.

ANTES DE SUBSTITUIR A VERSÃO ONLINE
- Faz uma cópia de segurança da base de dados e dos uploads.
- O esquema existente usa a base de dados data/marketplace.db; mantém esse ficheiro se quiseres preservar os anúncios e contas que contém.
- Depois do deploy, testa registo, login, atualizar a página, publicar anúncio com foto, pesquisa, mensagens e notificações usando duas contas diferentes.

LIMITES CONHECIDOS
Este pacote é uma melhoria de código e configuração, não uma certificação de produção. É necessário testar as rotas reais no Render. Para uma versão de produção mais robusta ainda se recomenda verificação de e-mail, recuperação de palavra-passe, moderação/denúncia de anúncios, proteção contra spam mais específica, backups automáticos, monitorização, armazenamento permanente das imagens e base de dados gerida.
